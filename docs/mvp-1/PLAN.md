## 1. 개발 목표와 실행 규칙

**목표:** 온통청년 정책을 수동으로 안정적으로 수집하고, 사용자가 정책을 탐색하며 나이·지역·취업·학력 조건을 입력하면 명확한 부적합만 제외하고 일치 항목 점수로 정렬한다. 목록·상세·신청 링크까지 MVP1에서 완성한다.

- **한 번에 Step 하나만 구현**한다. 각 Step은 원칙적으로 **커밋 하나의 작업 단위**다. 수정 파일이 많아지거나 독립적인 로직이 둘 이상 생기면 구현 전에 작업을 더 나눌지 보고한다.
- 각 Step의 체크박스는 **모두 충족한 뒤** 완료 표시한다. 관련 테스트가 실패했거나 미실행이면 이유를 보고하고 임의로 완료 표시하지 않는다.
- 순서는 기본적으로 앞에서 뒤로 진행한다. 독립 작업이라도 선행 조건(테이블, 타입, API 등)을 충족하기 전에 구현하지 않는다.
- `SPEC.md`가 세부 로직·값·예외 처리의 기준이다. 이 PLAN은 **작업 순서와 완료 조건**을 관리한다. 같은 내용을 다른 의미로 다시 정의하지 않는다.
- 작업 중 합의된 요구사항이나 구조가 달라지면 `AGENT_RULES.md`에 따라 **승인 후 관련 PRD/ARCHITECTURE/SPEC/PLAN을 함께 갱신**한다. 단순 설명 정정은 결과 보고에 기록한다.
- 사용자 지시 없이 다음 Step으로 넘어가거나 Git 커밋을 직접 실행하지 않는다. 각 Step 종료 후 `PLAN.md` 체크와 `SUMMARY.md` 실제 결과를 갱신하고 종료한다.
- 실제 API 인증키·공식 지역 코드표·검증된 취업/학력 코드표 등 **필수 자료를 구할 수 없으면 해당 Step을 보류**하고 원인을 보고한다. 추정 코드표나 가짜 API 결과로 완료 처리하지 않는다.
- `mvp-0/`는 기존 기록을 그대로 둔다. 이번 구현 기준 문서는 `mvp-1/`를 사용한다.

**공통 확인:** 해당 Step의 변경 범위 확인 → 필요한 최소 구현 → 단위/통합 테스트 → 정상·오류 동작 점검 → `PLAN`/`SUMMARY` 갱신 → 한국어 커밋 메시지 제안 → 중단.

**문서 준비:** 프로젝트 루트에 `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/AGENT_RULES.md`, `docs/mvp-1/SPEC.md`가 실제로 있는지 Step 1에서 확인한다. 이전에 받은 버전 표시 파일은 **내용을 대조한 후** 정식 위치에 배치한다.
