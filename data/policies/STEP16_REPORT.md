# Step 16 정책 표본 확장 및 Schema 재평가

기준일: 2026-10-10 (KST)

## 수집 범위와 재현 정보

- 공식 출처: [온통청년 정책 통합검색](https://www.youthcenter.go.kr/youthPolicy/ythPlcyTotalSearch)
- 공개 검색의 `마감 제외` 결과는 수집 시점에 752건이었다. 이 중 최신순 300건을 표본으로 읽었다.
- 기존 `policies.json` 30건과 정책명이 실질적으로 중복된 8건은 추가하지 않았다. 따라서 이번에 292건을 추가했고, 최종 표본은 322건이다.
- 추가 정책마다 온통청년의 개별 정책 상세 URL을 `officialUrl`로 저장했다. 목록에 없는 값을 추정하지 않았고, 조건의 기준이나 의미를 안전하게 정규화할 수 없으면 `UNKNOWN`과 추가 확인 메모로 남겼다.
- 목록의 세종특별자치시 전체 코드 `36110`은 이 프로젝트의 지역 seed가 사용하는 시·도 코드 `36`으로만 변환했다. 이외 seed에 없는 과거 인천 코드가 포함된 1건은 지역 조건을 `UNKNOWN`으로 유지했다.

## 조건 분포 (전체 322건)

| 조건 | ANY | RULE | UNKNOWN |
| --- | ---: | ---: | ---: |
| age | 145 | 164 | 13 |
| region | 0 | 321 | 1 |
| income | 262 | 3 | 57 |
| status | 256 | 27 | 39 |
| householdSize | 322 | 0 | 0 |

- 이번에 추가한 292건만 보면 age는 ANY 139 / RULE 153 / UNKNOWN 0, region은 RULE 291 / UNKNOWN 1이다.
- income RULE은 원문이 정확히 `기준 중위소득 N% 이하`인 경우만 3건으로 정규화했다. 연소득, 건강보험료, 도시근로자 소득, 매출 등은 현재 `IncomeRule`과 동치가 아니므로 `UNKNOWN`으로 남겼다.
- status RULE은 원문이 현 스키마의 `EMPLOYEE`, `UNEMPLOYED`로만 완전히 대응되는 경우에만 만들었다. 자영업자·프리랜서·일용·단기·영농·(예비)창업자는 억지로 기존 enum에 넣지 않았다.

## 미해결 자격 조건 빈도

전체 322건 중 202건은 최소 하나의 미해결 자격 조건을 가진다. 한 정책이 여러 항목을 가질 수 있으므로 아래 빈도 합계는 정책 수보다 클 수 있다.

| 유형 | 건수 |
| --- | ---: |
| 추가 신청자격 | 79 |
| 학력 | 54 |
| 소득 기준 | 36 |
| 제출서류 | 34 |
| 특화 대상 | 28 |
| 전공 | 27 |
| 고용형태 | 26 |
| 참여 우대대상 | 21 |
| 혼인 여부 | 7 |
| 지역 범위 | 1 |

`추가 신청자격`은 여러 이질적 문구를 담는 자유 텍스트라 독립적인 입력 필드 후보가 아니다. 상세 공고 확인을 유지해야 한다.

## 후보 재평가

### 유지

- age / region: RULE 비중이 높고 원문 값이 수치·행정코드로 명확하다. 현재의 `UNKNOWN 유지, MISMATCH만 제외` 원칙도 그대로 적합하다.
- status: 재직·미취업처럼 현재 enum과 정확히 대응되는 항목은 현재 모델을 유지한다. 다른 고용형태는 아래 추가 검토로 분리한다.
- income / householdSize: 현 UI의 보조 조건 위치를 유지한다. 소득은 안전하게 정규화 가능한 정책이 아직 3건뿐이고, 가구원 수 RULE은 이번 표본에서도 발견되지 않았다.

### 추가 검토

- 학력: 구조화된 학력 제한이 54건으로 반복되며, 재학·졸업예정·졸업·석박사 등 사용자 입력값도 명확하다. 다만 복수 학력 허용, 졸업예정 시점, 학교 유형을 하나의 안전한 rule로 설계한 뒤 추가해야 한다.
- 고용형태: 현 enum 밖의 고용형태가 26건에서 나타난다. 프리랜서·자영업·일용·단기·영농·(예비)창업을 별도 다중 선택 값으로 정의할 수 있는지 검토할 가치가 있다. 현재 `EMPLOYEE`로 합치면 잘못된 제외가 생길 수 있다.

### MVP2 이후

- 자산: 원문 자격 관련 문구 출현 19건. 금융자산·부동산·자동차·가구 합산 등 측정 단위가 달라 단일 숫자 rule로 정규화하기 어렵다.
- 주택 조건: 원문 문구 출현 36건. 무주택, 임차, 보증금, 주택가격, 거주기간이 혼재하므로 단순 boolean은 검색 품질을 해칠 수 있다.
- 사업체 규모·매출: 원문 문구 출현 26건. 중소기업 여부, 소상공인, 매출 기준이 서로 다른 사용자/사업체 정보다.
- 혼인: 구조화된 제한은 7건이다. 입력값은 명확하지만, 배우자·자녀·신혼부부 조건과 결합되는 비율이 높아 독립 추가의 효과가 아직 작다.
- 병역: 원문 문구 출현 8건. 복무 중, 제대군인, 연령 연장 등 시간 기준이 달라 단일 선택으로 안전하게 처리하기 어렵다.
- 근속기간·재직기간 및 성적: 각각 원문 문구 출현 4건이다. 빈도가 낮고 기준 기간·학점/등급 형식이 달라 우선순위를 낮춘다.
- 장애, 한부모·자녀, 수급·차상위, 거주·전입기간도 반복되지만 대상자 정의와 증빙·가구 관계가 다양하다. 현 단계에서는 `manualCheckNote`가 더 안전하다.

문구 출현 빈도는 설명·지원 내용까지 포함한 단순 탐색 수치이며, 곧바로 자격 필드 반복을 뜻하지는 않는다. Schema 후보 판정에는 위의 구조화된 미해결 조건 빈도를 우선 사용했다.

## 결론

현재 schema와 migration은 변경하지 않았다. 다음 schema 후보는 **학력**, 그 다음은 **세분화된 고용형태**다. 두 후보 모두 반복성·입력 명확성은 충족하지만, 정책 간 의미를 안전하게 하나의 rule로 정규화하는 설계와 검색 품질 검증이 먼저 필요하므로 MVP1에서는 추가하지 않는다.
